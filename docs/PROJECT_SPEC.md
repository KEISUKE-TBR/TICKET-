# TICKET- / Card Studio プロジェクト仕様書

## 1. 目的

CSV / TSV のデータを名刺サイズのカードへ差し込み、必要なレコードだけを選択して、ELECOM MT-HMN2WNR 用紙へ正確に印刷できるブラウザアプリを作る。

同時に、テキスト・画像・QRコード・図形を自由に配置できる、Figmaに近い直感的な編集体験を目指す。

## 2. 対象ユーザー

- デザインツールに詳しくないイベント運営者・店舗スタッフ
- CSVで送り主、メッセージ、URLなどを管理する担当者
- 家庭用または業務用プリンターでカードを印刷する担当者
- テンプレートを作成・再利用するデザイナー

## 3. MVP機能

### エディター

- 86×54mm 横カード
- 54×86mm 縦カード
- テキスト、画像、QRコード、長方形、楕円、線
- 選択、移動、拡大縮小、回転、削除、複製
- Undo / Redo
- ズーム
- レイヤー一覧
- 表示 / 非表示
- ロック
- 前面 / 背面移動

### データ差し込み

- CSV / TSV インポート
- 1行目をヘッダーとして使用
- 列名一覧とレコード一覧を表示
- テキスト要素をCSV列へバインド
- QRコードをCSV列から再生成
- レコードごとのプレビュー
- レコードごとの上書き値
- 印刷対象レコードの複数選択

### 保存

- LocalStorageへの自動保存
- JSON形式のプロジェクト書き出し / 読み込み
- 保存データに `schemaVersion` を持たせる

### PDF / 印刷

ELECOM MT-HMN2WNR プリセットを使用する。

- 用紙: A4縦 210×297mm
- カード: 86×54mm
- 配置: 2列×4行、8面
- 左右余白: 14mm
- 上下余白: 25.5mm
- 横方向間隔: 10mm
- 縦方向間隔: 10mm
- 8件を超える場合は次ページへ送る
- 選択したレコードだけを印刷する
- 印刷倍率は100% / 実際のサイズ

## 4. 技術方針

現在の単一HTML版は、DOMを毎回再生成する構造のため、画像ドラッグ中に操作対象が置き換わり、ドラッグが壊れる問題がある。

今後は以下を基本構成とする。

- React
- TypeScript
- Vite
- Konva / react-konva
- Zustand
- pdf-lib
- Playwright
- Vitest

### 最重要設計原則

- DOMベースの疑似キャンバスへ戻さない
- KonvaのScene Graph上でキャンバス操作を行う
- ドラッグ中はアプリ全体を再描画しない
- 移動結果は `dragEnd` でStoreへ確定する
- PDFは画面のスクリーンショットではなく、プロジェクトモデルから描画する
- mm / px / PDF point の変換を1か所へ集約する

## 5. 最重要受入条件

1. 画像を追加した直後に選択できる
2. 画像そのものをドラッグできる
3. 同じ画像を10回連続でドラッグしても停止・ジャンプしない
4. 拡大縮小・回転後に再読み込みしても状態が保持される
5. CSV列をテキストへ割り当て、レコード切替で表示が変わる
6. QRコードがレコード値に応じて再生成される
7. 選択したレコードだけがPDFへ出力される
8. 9件選択時、1ページ目8面・2ページ目1面になる
9. JSON書き出し後に読み込み直しても状態が一致する

## 6. テスト方針

- Unit: 単位変換、CSV解析、差し込み評価、印刷座標
- Component: レイヤー選択、プロパティ変更、エラー表示
- E2E: 画像ドラッグ、CSV取込、レコード切替、JSON復元、PDF生成
- Manual: Chrome上で実際に操作して確認

## 10. 現在の既知問題

単一HTML版の `renderAll()` がドラッグ開始直後および `pointermove` ごとにキャンバスDOMを再生成している。そのため、ドラッグ対象要素が操作中に置き換わり、特に画像ドラッグが不安定になる。

この問題はCSS調整ではなく、React + Konvaへの構造移行で解消する。
